

    IONICIAR O PROJETO DJANGO COM Docker

        Como o seu projeto está configurado com Docker Compose e possui um script de inicialização automatizado (scripts/command.sh), o processo para reiniciar o ambiente é bastante simples.

        Siga estes passos no seu terminal:

            Acesse a pasta do projeto:

                $ cd /home/delll/Projects/djangoProject
            
            Suba os containers: Você tem duas opções principais:

                Opção A (Com logs no terminal): Ideal para ver o que está acontecendo em tempo real.

                    $ docker compose up
                    (Para parar, pressione Ctrl+C)

                Opção B (Em segundo plano/Detached): Ideal se você quiser liberar o terminal para rodar outros comandos (como criar apps ou superusuários).

                    $ docker compose up -d
                    (Para parar depois, use docker compose down)

            O que acontece automaticamente quando você roda esse comando? 
            Graças ao seu arquivo scripts/command.sh, o Docker irá:

                - Iniciar o banco de dados PostgreSQL.
                - Aguardar o banco estar pronto para conexão.
                - Rodar as migrações pendentes (migrate).
                - Coletar arquivos estáticos (collectstatic).
                - Iniciar o servidor Django na porta 8000.
        
        Após o comando, basta acessar no navegador: http://localhost:8000/




    # Subir as imagens do Docker
    # docker compose up

    # URL Acesso
    http://localhost:8000/


    # Acessar o Painel Administrativo
    http://localhost:8000/admin/

    # Backup do Projeto "/home/delll/Projects/djangoProject"

        Para que o script de backup funcione, os containers do Docker precisam estar rodando.

        Para facilitar, criei um script backup.sh dentro da sua pasta scripts/. Este script cria uma pasta datada, faz o dump do banco, copia os arquivos de mídia e o .env, e compacta tudo em um arquivo .tar.gz.
        Arquivo em:   /home/delll/Projects/djangoProject/scripts/backup.sh
        
        Como usar o script:
        
             1. Dê permissão de execução:
                    chmod +x scripts/backup.sh

            2. Execute o backup: Na raiz do projeto   (/home/delll/Projects/djangoProject):
                    ./scripts/backup.sh
                
                Isso criará uma pasta backups/ com um arquivo .tar.gz contendo tudo o que você precisa para restaurar o projeto.

        
        Como Restaurar (Caso precise)

            1. Banco de Dados:

                # Descompacte o arquivo sql
                # Verifique o usuário (POSTGRES_USER) e o banco (POSTGRES_DB) no seu arquivo ./dotenv_files/.env
                # e substitua no comando abaixo se forem diferentes.
                # Exemplo para restaurar (baseado no seu .env):
                    cat db_dump.sql | docker compose exec -T db psql -U usr_postgres -d db_postgres


            2. Arquivos de mídia:

                Basta extrair a pasta media e copiar de volta para o local mapeado no seu volume ou container.

    Conteúdo-chave dos arquivos (resumo)

        docker-compose.yml
            backend: build a partir de docker/django/Dockerfile; mapeia ./src/backend:/app; porta 8000; usa .env; depende de db

        docker/django/entrypoint.sh
            Espera o DB, roda migrate e inicia o servidor em 0.0.0.0:8000

        src/backend/manage.py
            Gerenciador padrão do Django

        src/backend/config/wsgi.py

        .env.example
            Modelo com variáveis: DJANGO_SECRET_KEY, DEBUG, DJANGO_ALLOWED_HOSTS, POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, DB_HOST, DB_PORT

        .gitignore
            Previne commit de secrets, ambientes virtuais etc.

            Instruções básicas de uso

        .env.example
            Modelo de configuração para o ambiente de desenvolvimento

        README.md (novo conteúdo descrevendo o setup)



    Como usar (fluxo recomendado)

    1. Duplicar o env de desenvolvimento
        cp .env.example .env
        Editar .env com valores reais (DB_HOST=db, POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD etc.)

    2. Construir e iniciar
        docker compose up --build

    3. Migrações e usuário admin (opcional, para já ter admin)
        docker compose exec backend python manage.py migrate
        docker compose exec backend python manage.py createsuperuser

    4. Acessar
        http://localhost:8000/ deve retornar a raiz porque criamos uma view simples para ela
        /admin/ para o painel do Django admin
